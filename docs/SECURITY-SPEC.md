# 三江资源：网站安全设计与实现规范

版本 1.0 · 2026-10-21 · 适用于本仓库（Astro SSR + SQLite + Nginx 反向代理）及后续同类站点。
本文是**约束**，不是建议清单：标注「必须」的条款在代码评审与发布门禁中逐条检查；需要偏离时走 §13 的例外流程。

## 1. 威胁模型与设计原则

### 1.1 假设的攻击者

| 角色 | 能力 | 关注点 |
|---|---|---|
| 匿名访客 | 任意构造 HTTP 请求、可分布式、可伪造任意请求头 | 注入、枚举、资源耗尽、统计污染 |
| 被攻陷的编辑者账号 | 可写草稿、可触发链接检查、可提交反馈 | 越权、存储型 XSS 打管理员、SSRF |
| 被攻陷的管理员账号 | 全部后台能力 | 数据完整性、审计可追溯性 |
| 拿到会话令牌的人 | 可重放 Cookie | 会话生命周期、撤销能力 |
| 运维误配 | 代理配置、环境变量、暴露端口 | 身份退化、全站共享配额、明文暴露 |

### 1.2 五条不可协商的原则

1. **服务端是唯一裁判。** 前端的隐藏、禁用、校验都只影响体验，不构成控制。
2. **身份来自连接，不来自请求体/请求头。** 任何"客户端说自己是谁"的值，只有在部署契约明确时才可采信（见 §2）。
3. **默认拒绝，显式放行。** 路由、方法、字段、URL scheme、出站目标、事件名都用允许列表。
4. **失败要安全。** 拿不到可信身份 → 退化为**站点级保护**而不是"人人共享小额度"；拿不到解析结果 → 不发起请求；渲染出错 → 不输出未转义内容。
5. **可用性也是安全属性。** 限流的目的是挡住滥用，不是让一个人能关掉所有人的入口。任何"一人可影响全体"的机制必须显式评审。

## 2. 身份与信任边界

### 2.1 客户端身份（必须）

- 应用**必须**通过唯一入口 `clientIdentity()`（`src/server/security.ts`）取得限流身份，禁止在业务代码里直接读 `X-Forwarded-For` / `clientAddress`。
- 代理**必须**覆盖写入客户端地址，禁止追加：

  ```nginx
  proxy_set_header X-Forwarded-For $remote_addr;
  proxy_set_header X-Real-IP       $remote_addr;
  ```

- 仅当 `TRUST_PROXY=1`（声明"应用只能经自己的代理访问"）时，才采信单值 `X-Forwarded-For`；以下情况一律返回 `unverified-peer` 并走站点级熔断：
  - 头缺失或为空；
  - 值不是合法 IP 字面量；
  - 值包含多个地址（多跳链）。
- 端口暴露**必须**与信任声明一致：`docker-compose.yml` 只绑定 `127.0.0.1`；若把 4321 直接对公网开放，必须同时置 `TRUST_PROXY=0`。
- 接入 CDN 时，只允许在 Nginx 用 `set_real_ip_from <CDN 网段>` + `real_ip_header` 还原 `$remote_addr`，应用代码不变、信任声明不变。

### 2.2 站点来源（必须）

- `SITE_URL` 是唯一权威 origin：canonical、分享链接、Origin 校验、Cookie `Secure` 全部由它派生，禁止用 `Host` 头推导（`requireOrigin()` 已按此实现）。
- 写操作**必须**校验 `Origin` 精确等于 `SITE_URL` 的 origin；`Sec-Fetch-Site` 存在时必须为 `same-origin`/`none`。
- 禁止引入 CORS 通配（`Access-Control-Allow-Origin: *`）；确需跨域时按白名单逐条登记。

### 2.3 会话 Cookie

- 名称与属性：`HttpOnly; SameSite=Strict; Path=/`，HTTPS 下必须 `Secure`，建议使用 `__Host-` 前缀。
- 令牌**必须**是 ≥256 bit 的 CSPRNG 值，服务端只存哈希。
- 禁止把会话标识放进 URL、日志、错误信息或埋点。

## 3. 输入、输出与渲染

### 3.1 输入处理（必须）

- 每个入口**必须**先声明 schema（zod 或等价物），显式列出字段、类型、长度、枚举；未知字段丢弃而不是合并。
- 长度与复杂度上限（沿用并作为基线）：普通表单 ≤96 KiB、导入 JSON ≤3 MiB（代理侧 4m）、事件体 ≤2 KiB、Markdown ≤20 000 字符、反馈正文 10–4 000、标题 ≤150、用户名 `[a-z0-9_.-]{3,64}`、口令 12–256。
- **预检与提交必须使用同一上限**：预检放行的体积，提交不能 413；反之亦然。新增任何"预览/确认"两步流程时，把这条写进测试。
- 结构化 ID **必须**正则约束（如 `^[a-z0-9-]{1,80}$`），禁止把原始字符串拼进 SQL、路径、文件名或 URL 模板。
- ID/slug **必须**避开与路由冲突的保留标识（当前为 `new`）：`/admin/resources/new/` 是"新建"页，条目取该 ID 后无法再编辑。保留字表集中在 `src/lib/identifiers.ts`。
- 分类标识**必须**避开虚拟书架 `all`：它是前台"全部资源"入口，存进 `categories` 表后既不能当场景使用也无法在后台改名。分类的所有写入口（分类管理、导入预检、导入应用）共用 `isReservedCategory()`。
- 实体 ID / slug 的长度上限**必须**只有一处定义（`MAX_IDENTIFIER_LENGTH`），schema、事件上报与统计共用；禁止在统计层再截断实体 ID——截断会把"前 N 字符相同"的两个条目合并计数。只有自由文本（零结果搜索）允许归一化与截断。
- "预检 → 确认"两步流程**必须**把用户在预检时看到的状态冻结下来（版本号 + 内容摘要），应用时逐条校验，**禁止**用应用时重新查询的版本号代替。任何一条不匹配就整批取消并提示重新预检。
- 批次导入**必须**保证单条事务完整性：一个条目的"恢复出回收站 + 写入 + 版本记录 + 审计"在同一事务内，失败不留半截状态。
- SQL 只允许参数化语句；禁止字符串拼接查询。动态排序/列名必须来自常量映射。
- 重复字段、类型混淆（数组当字符串）、`__proto__`、超长 multipart 一律拒绝（`text()` 已做重复字段拒绝）。

### 3.2 输出编码（必须）

- 模板默认转义；**禁止** `set:html`/`innerHTML`/`dangerouslySetInnerHTML` 处理用户内容。确需富文本时只能走 §3.3 的白名单渲染器。
- 同一个值进入不同上下文必须按上下文编码：HTML 文本、属性、`<title>`、`<meta content>`、JSON-LD（`<` → `\u003c`）、URL 参数、CSS。历史缺陷正是"属性里不转义 `<` 虽然当前无害，但缺少统一规则"。
- 错误页**禁止**回显原始输入（除显式标注为草稿的字段，且必须转义）。
- 禁止把用户输入拼进 `Location`、`Set-Cookie`、`Content-Disposition`（文件名用固定模板 + 日期）。

### 3.3 Markdown

- 渲染器**必须** `html: false`；链接 scheme 只允许 `http/https/mailto`，其余（`javascript:`、`data:`、`vbscript:`、反斜杠变体）按纯文本输出。
- 外链**必须**带 `rel="noopener noreferrer"`；禁止 `target=_blank` 不带 `rel`。
- 图片只允许站内路径（`/images/...`），禁止远程图片与 `data:`。

### 3.4 文件与路径

- 用户可控值**禁止**参与文件系统路径拼接；静态资源只从 `public/` 白名单目录提供。
- 任何"按 ID 取文件/目录"的逻辑必须走规范化 + 前缀校验，并在测试中覆盖 `..`、`%2e%2e`、编码斜杠、反斜杠、空字节。

## 4. 认证、会话与口令

### 4.1 口令

- KDF：scrypt（现状）或 Argon2id；每个口令独立随机盐；校验用恒定时间比较。
- 口令长度 12–256；**必须**拒绝包含 NUL；建议在线提示常见弱口令与"品牌+年份+符号"模式。
- 用户不存在时**必须**执行一次等价的 dummy 校验，保证时序一致（`verifyPassword` 已实现）。

### 4.2 登录限流（必须，按本仓库实现为准）

- 维度分层，语义明确：

  | 维度 | 额度 | 窗口 | 计数对象 |
  |---|---|---|---|
  | `login-user`（账号） | 10 | 15 分钟 | **仅失败**，成功后清零 |
  | `login-client`（客户端身份） | 30 | 15 分钟 | **仅失败** |
  | `login-site`（熔断，可选） | 500 | 5 分钟 | 全站失败总数，仅用于分布式攻击压制 |

- 禁止把"成功登录"计入额度（历史缺陷：运维自锁）。
- 429 **必须**返回真实剩余时间的 `Retry-After`（由 `reset_at - now` 计算），禁止硬编码常量。
- 429 的正文不得区分"账号是否存在""是否被锁"。

### 4.3 会话生命周期

- 默认 8 小时；服务端存哈希；登录时清理过期会话，并限制单账号并发会话数（现状 10）。
- **必须**提供"退出当前会话"；**应**提供"退出其他/全部会话"与设备列表（IP/UA 只存哈希）。
- 改密、停用、角色变更**必须**撤销该账号全部会话。
- CSRF 令牌**应**为每会话独立随机值并支持轮换（现状由会话令牌派生，可接受但不可轮换）。

### 4.4 口令重置与账户恢复

- 本项目无邮件找回：**必须**提供运维路径（CLI 新建管理员 / 直接清理限流键），并在文档中写明；禁止通过"安全问题"恢复。

## 5. 授权

- 角色矩阵固定为 `admin` / `editor`，能力差异见 `README.md`；新增能力**必须**同时更新矩阵与测试。
- 每个写操作**必须**在服务端重新读取操作者当前角色（`actorUser()`），不信任会话里缓存的角色。
- 对象级授权**必须**验证对象归属关系（例如反馈关联的修订必须属于该反馈关联的资源，`updateReport` 已实现）。
- 禁止仅靠"页面 302/隐藏按钮"实现权限；测试**必须**包含直接用 HTTP 调用越权接口的用例。
- 所有变更**必须**写审计（谁、何时、对什么、结果），审计写入与业务变更同事务。

### 5.1 并发与"用户看到的状态"（必须）

- 所有带 `version` 的写操作**必须**做版本校验（`409` 而不是覆盖），导入、恢复、发布、保存都一样。
- 两步操作**必须**绑定第一步的结果：预检冻结 `{版本, 摘要}`，提交时校验摘要（内容是否被改）与逐条版本（是否被别人保存）；不匹配就整批拒绝。
- 恢复历史版本前**必须**校验历史数据的外部依赖（如分类是否还存在）。缺失依赖要给出可操作的提示（"选择替代分类"），禁止让它变成外键错误/通用 500。
- 批量操作**必须**区分"批次原子"与"条目原子"：本仓库选择条目原子（允许部分成功），因此每条都必须自成事务，且失败条目的副作用（恢复、计数、状态）必须回滚。
- 关系的删除**必须**由用户显式发起：候选列表里"看不见"的关联项不能等价为"用户要删除它"。回收站中的被关联对象要照常展示并标注状态，新增这类关联则在服务端拒绝。
- 版本号不足以识别"同一个对象"：实体**必须**带不可复用的身份（`resources.uid` / `guides.uid`），且**版本号永不复用**——`purge` 时写入 `entity_versions` 墓碑，同名重建从"最后版本 + 1"继续编号。这样任何只带 `version` 的旧表单都不可能匹配到新对象；`uid` 用于导入计划给出"已被删除并重建"的明确提示。
- 预检与提交的**条目筛选规则必须一致**：预检判定为语义无效（分类缺失、关联资源不存在）的条目，提交时应作为逐条错误返回，不能整批 409 要求"重新预检"，否则合法条目会被无效条目永久拖住。
- 两步操作冻结的**必须**是该流程会写入的全部目标状态，不只是文件内容：导入恢复设置时同样要冻结"当前设置摘要"，预检后被别人改过就整批取消。
- 批量决断（批量复核、批量状态变更）**必须**绑定操作者看到的那一版；期间被修改的条目要跳过并明确计数，禁止把对旧内容的核准套给新内容。
- 反馈、备注这类"人工结论"字段**必须**做版本校验（或改为追加式记录）。审计只记录谁在何时对什么做了什么，不能用来恢复被覆盖的正文。
- 客户端的未保存备份**必须**按编辑会话分键（`sessionStorage` 会话标识 + 实体键）；保存成功只能清理自己的备份或内容完全一致的副本，别人的输入必须保留且可恢复。
- 迁移/导入的结果明细**必须**可回查（落库并限制保留条数）。只在重定向参数里带数量，等于把"哪一条失败、为什么"丢掉。

## 6. 限流与可用性设计（本项目最重要的一节）

### 6.1 分层模型

限流**必须**按"对象"分层，每层有明确语义，禁止用一个桶承担全部语义：

| 层 | 目的 | 容量原则 | 耗尽时的行为 |
|---|---|---|---|
| 账号层 | 抗口令猜测 | 小（10/15min） | 拒绝该账号的**失败**尝试 |
| 客户端层 | 抗单点滥用 | 中（30/15min、5/h、600/h） | 拒绝该客户端 |
| 站点层 | 抗分布式攻击 | 大（≥正常峰值 10 倍） | 拒绝或**采样降级** |

### 6.2 硬性规则

1. **身份必须可区分**：如果部署让所有请求共享一个身份，就等于把"客户端层"变成了"站点层"。上线前必须验证 `rate_limits` 里出现多个不同的客户端键。
2. **窗口与文案必须一致**：`Retry-After` 由数据算出；窗口长度集中定义（禁止散落的魔法数字）。
3. **计数语义显式**：区分"请求计数"（反馈、指标）与"失败计数"（登录）；成功路径不得扣额度。
4. **容量必须可运营**：任何全站级阈值都要有监控与告警；命中率、429 比例、Top 客户端必须可观测（日志不含 PII）。
5. **耗尽要优雅**：统计类写入耗尽后**应**降级为采样而不是全丢；不可让"统计"影响"页面可用"。

### 6.3 事件/指标类接口专项

- 匿名写入**必须**：同源校验 + 体积上限 + 事件名允许列表 + **目标实体校验**（只接受已发布资源/指南）。
- 目标未知时**必须**静默丢弃（2xx/204），不得返回可区分信息。
- 每（天, 事件, 目标）**必须**有去重与容量上限（现状：每事件每日 200 个不同目标），防止 Top 榜被污染。
- 指标数据**必须**标注保留期与清理任务（现状 90 天）。

## 7. 出站请求（SSRF）

任何由用户 URL 触发的服务端请求（链接检查、未来的 webhook/抓取）**必须**满足：

1. 协议白名单 `http/https`；端口白名单 `80/443`；拒绝带凭据的 URL。
2. **先解析、再校验、后固定连接**：解析结果逐条判私网/保留地址；实际连接**必须**使用已校验的 IP（DNS pinning），禁止让 `fetch` 再解析一次（防 rebinding/TOCTOU）。
   - 固定连接失败（依赖加载失败、lookup 异常、socket/TLS 错误、超时）**必须**终止本次检查并记为 error；**禁止**回退到会重新解析域名的普通 `fetch`——回退等于把 DNS 重绑定原路放回。宁可检查失败，也不能发一次未校验的请求。
   - 自定义 `lookup` 实现**必须**满足 Node 的双契约：`options.all === true` 时回调地址数组（`{address, family}[]`），否则回调 `(address, family)`；只实现单地址形式会触发 `Invalid IP address: undefined`，进而诱导实现者写出"失败就回退"的补丁。
   - 校验与连接**必须**共用同一个解析器：一旦校验用系统 DNS、连接用另一次解析，"两次答案不同"就重新成为绕过路径。
3. 重定向**必须**手动处理，每一跳重新校验并重新固定；跳数上限 3。
4. 超时（10 s）、响应体上限（32 KiB）、方法优先 HEAD、`redirect: manual`。
5. 出站请求**必须**限速（按操作者），并记录结果（状态码、耗时），不记录响应体。
6. 检查结果**必须**记录"被检查的目标 + 内容版本 + 检查对象"（URL、行版本、`draft`/`published`），目标或版本变化后**必须**标记过期并要求重新检查；禁止把旧结果当作当前结论。
   - 草稿检查：链接或草稿版本变化即过期。
   - 公开快照检查：只认公开快照（撤回或重新发布后链接不同即过期）；"草稿改了但还没发布"不算过期。
   - 过期判断**必须**只有一份实现（`linkCheckStaleReason()`），列表页与详情页共用；定时脚本与手动按钮都必须写入完整的检查目标。
7. 私网判定**必须**基于地址字节而不是字符串正则。URL 解析器会把 `http://[::ffff:127.0.0.1]/` 规范化成 `[::ffff:7f00:1]`，任何"只在点分形式里匹配 IPv4"的实现都会把回环地址放行。
   - IPv4：`0/8`、`10/8`、`100.64/10`、`127/8`、`169.254/16`、`172.16/12`、`192.0.0/24`、`192.0.2/24`、`192.88.99/24`、`192.168/16`、`198.18/15`、`198.51.100/24`、`203.0.113/24`、`224/4`、`240/4`。
   - IPv6：`::/96`（含 `::`、`::1`）、IPv4-mapped `::ffff:0:0/96`（取低 32 位按 IPv4 规则判）、NAT64 `64:ff9b::/96`（同上）、6to4 `2002::/16`（内嵌 IPv4，按 IPv4 判）、6bone `2001::/32`、文档前缀 `2001:db8::/32`、组播 `ff00::/8`、唯一本地 `fc00::/7`、链路本地 `fe80::/10`、站点本地 `fec0::/10`。
   - 解析失败**必须**按危险处理（fail closed）；URL 字面量、DNS 答案、每一跳重定向统一使用同一判定器。回归用例**必须**从真实 URL 与重定向路径进入，不能只测点分字符串。
   - 回归**必须**包含 DNS 重绑定（首次公网、后续私网）、固定连接失败（断言没有任何未校验请求发出）、逐跳重定向校验与正常域名成功四类；危险场景**必须**断言本地回环服务收到 **0 次**请求，而不只是看返回值。
7. 部署层**应**配合出站防火墙/egress 白名单，应用层校验只是第一道。

## 8. 数据、隐私与日志

- 收集最小化：指标只存 `日/事件名/目标/计数`，不存 IP、UA、账户；搜索词截断并设保留期。
- 日志**禁止**记录：Cookie、CSRF、口令、查询串中的敏感值、原始 IP（如需排障，存哈希+短期）。
- 备份**必须**放在仓库之外、权限 0600、加密存储；恢复流程每季度演练一次。
- 导出功能只包含内容数据，**禁止**包含口令哈希、会话、反馈正文之外的私密字段（现状导出仅 `categories/resources/guides/settings`）。
- 删除/下架**必须**可追溯（版本历史 + 审计），purge 是不可逆操作，需要二次确认。

## 9. 部署与运维基线

### 9.1 TLS 与代理

- 只允许 HTTPS 对外；HTTP 301 到 HTTPS；`SITE_URL` 与浏览器地址完全一致。
- HSTS 在证书与域名稳定后开启（`max-age=15552000; includeSubDomains`），先在预发验证。
- `server_tokens off;`；`client_max_body_size` 与应用上限保持一致并写明。
- 反向代理与应用之间只走本机/私网；应用端口不对公网暴露。

### 9.1b 边缘与源站暴露（必须）

- 使用 CDN 时，源站**必须**只接受 CDN 回源段与运维 IP 的连接（`return 444`），直连一律丢弃；443 用 `ssl_reject_handshake` 或默认占位证书处理未知 SNI。
- 反向代理**必须**先还原真实客户端地址（`set_real_ip_from` + `real_ip_header`），再做任何按 IP 的限流；白名单判断**必须**用改写前的 `$realip_remote_addr`，限流/日志用改写后的 `$remote_addr`。
- 边缘层**应**配置 `limit_req` / `limit_conn` 抗 CC，并与应用层限流分工：边缘负责量，应用负责业务语义（失败次数、配额、写入去重）。
- 回源 IP 段**必须**纳入例行核对（每次 CDN/DCDN 变更后），变更记录写入部署文档。
- 详细配置、验证命令与"CDN 被切沙箱"应急预案见 [边缘防护](edge-cdn-hardening.md)。

### 9.2 安全响应头（必须）

| 头 | 值 | 说明 |
|---|---|---|
| `Content-Security-Policy` | 先 `Report-Only`，收集后转强制 | 禁止内联脚本是目标；迁移期允许 `'unsafe-inline'` 并登记为技术债 |
| `Strict-Transport-Security` | `max-age=15552000; includeSubDomains` | 仅 HTTPS 站点下发 |
| `X-Content-Type-Options` | `nosniff` | |
| `X-Frame-Options` | `DENY`（或 CSP `frame-ancestors 'none'`） | |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=(), payment=(), usb=()` | |
| `Cache-Control` | 公开页可短缓存；后台与 API `no-store` | 含用户数据的响应必须 `no-store` |

### 9.3 健康检查与信息暴露

- `/api/health/` 只返回 `status`、`db`；`schema`、`uptime`、版本号等内部信息移到需要鉴权的端点。
- 404/400 页面不得回显路径、栈、SQL、内部主机名。
- 生产关闭详细错误；异常只记录 `error.name` 与 request id。

### 9.4 依赖与供应链

- 锁定 `package-lock.json`；CI 必须 `npm ci`。
- 定期跑 `npm audit`（或 Dependabot）；高危必须在发布前处理或登记例外。
- 新增运行时依赖需评审：体积、维护状态、许可证、是否引入原生模块；本仓库仅允许少量显式依赖（`undici` 用于固定连接）。

### 9.5 发布门禁

`npm run check` + `npm test` 全绿；涉及认证/限流/渲染的改动**必须**附带回归用例；安全相关 PR 需要第二人复核。

## 10. 编码规范（安全相关，强约束）

1. 一个功能只有一个"权威实现"：身份 → `clientIdentity()`；限流 → `enforceLimits/consumeLimit/rateLimit`；URL 校验 → `resolvePublicTarget()`；Markdown → `renderMarkdown()`；口令 → `hashPassword/verifyPassword`。禁止在业务代码里复制粘贴这些逻辑。
2. 错误统一走 `fail(status, message)` / `errorResponse()`；禁止 `throw new Error` 直接冒泡到用户。
3. 所有 `catch` 必须决定"记录/转换/降级"，禁止空 catch 吞掉安全相关异常。
4. 事务边界清晰：限流计数、审计、业务变更要么同事务，要么有明确顺序与补偿说明。
5. 注释必须解释**为什么**（尤其是安全取舍），而不是复述代码；`address()` 那次的教训是"注释写了意图，代码没做到"。
6. 提交前自查清单：
   - 新字段有没有长度/枚举约束？
   - 新输出点在哪个上下文？转义了吗？
   - 新写操作有没有服务端角色校验与审计？
   - 新出站请求走 `resolvePublicTarget` 了吗？
   - 新限流维度会不会让一人影响全体？窗口与 `Retry-After` 一致吗？
   - 新增错误路径会不会泄露存在性/内部信息？

## 12. 事件响应与例行工作

- 每周：检查 429 比例、登录失败 Top 客户端、指标事件量异常、依赖告警。

## 13. 例外与变更流程

1. 任何偏离本规范的实现**必须**在 PR 描述中写明：偏离哪条、原因、影响、补偿措施、到期时间。
2. 例外登记在 issue 中，标记 `security-exception` 与到期日；到期未修复则阻断发布。
3. 新增"跨用户/跨租户"能力、新增出站请求、新增匿名写入接口、放宽任何白名单，**必须**做一次专项评审（威胁模型 + 滥用场景 + 限流设计）。
